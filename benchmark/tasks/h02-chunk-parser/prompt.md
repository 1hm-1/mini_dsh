# Delimited records change when the input is chunked

The import path in `src/index.mjs` serves two consumers: one returns parsed items, and one counts them. The input is already an array of string chunks, but chunks may end anywhere, including between the two characters of `\r\n` or between doubled quotes. Currently some records split differently depending on those boundaries. Fix the shared parser so both consumers see the same records and errors. Preserve the named exports `parseRows`, `readItems`, and `countItems`, and leave the public tests unchanged.

This is a deliberately small delimited format, not a general CSV dialect. A record has fields separated by literal commas. A field is either unquoted text, which may contain any characters except comma, double quote, CR, or LF, or quoted text starting with `"` at the field beginning. Inside a quoted field, commas and line breaks are literal field content; two adjacent double quotes `""` become one literal `"`. A closing quote must be followed by comma, record ending, or end of input. Outside quotes, records end at LF or CRLF; a bare CR is invalid. Preserve field content exactly, including spaces and CRLF inside quotes. Do not trim fields. Empty fields and blank lines are allowed: an empty line parses as `['']`. A final record without a line ending is included, while a final line ending does not add another empty record. Empty input produces `[]`. Joining the chunks first must not change the result, and empty chunks are allowed.

`parseRows(chunks)` returns an array of arrays of strings. `chunks` must be an array of strings; otherwise throw `TypeError`. Syntax failures throw `SyntaxError` with a `.code` string: `INVALID_QUOTE` when a quote occurs inside unquoted text or any non-delimiter follows a closing quote; `UNTERMINATED_QUOTE` for an open quoted field at end of input; and `BARE_CR` when a CR outside quotes is not immediately followed by LF, including at end of input. No other escaping is recognized.

`readItems(chunks)` and `countItems(chunks)` consume the same parser result. Every record must have exactly two fields, `id,note`, with a nonempty `id`; the note may be empty. `readItems` returns `{ id, note }` objects in order and `countItems` returns their count. Either consumer throws `SyntaxError` with `.code` `COLUMN_COUNT` for a row with another number of fields or `EMPTY_ID` for an empty id. Parser syntax errors propagate unchanged through both consumers. An empty input returns `[]` and `0` respectively.

The package also has independent slug and checksum helpers that are outside this parser issue. Their existing behavior needs no change. The external checks cover the grammar above and old utility behavior; they do not require a larger parser or streaming I/O interface.
