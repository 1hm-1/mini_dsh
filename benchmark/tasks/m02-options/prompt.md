Extend the formatting options across all three modules. Keep the existing exports `DEFAULT_OPTIONS`, `resolveOptions(overrides)`, and `formatValue(value, overrides)`.

The existing behavior remains: by default `formatValue(12.345)` returns `"12.35"`; `{ precision: 1, prefix: '~' }` returns `"~12.3"`. Add `unitLabel`, a string option whose default is the empty string. If nonempty, append one space and the label after the formatted number, for example `formatValue(12.3, { unitLabel: 'kg' })` returns `"12.30 kg"`; with prefix and precision it returns `"~12.3 kg"`. `DEFAULT_OPTIONS` must expose all three defaults `{ precision: 2, prefix: '', unitLabel: '' }` and must never be mutated. `resolveOptions()` and `resolveOptions(overrides)` return a fresh object with defaults overridden by the supplied own fields. Reject a non-object, null, or array override with `TypeError`; `undefined` means no overrides. Reject unknown keys with `TypeError`. Precision must be an integer from 0 through 4 (`RangeError` otherwise); prefix and unitLabel must be strings (`TypeError` otherwise). `formatValue` accepts only finite numbers (`TypeError` otherwise), delegates option resolution to `resolveOptions`, and preserves the old call forms without requiring the new field. Calls and returned objects must not share mutable state.
